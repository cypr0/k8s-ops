# dmarc-exporter

> **Namespace**  mail
> **Source**     Plain manifests (container image: `jgosmann/dmarc-metrics-exporter`)
> **Hostname**   None (internal metrics endpoint only)

## What it does here
Polls a dedicated IMAP mailbox (`dmarc@${SECRET_DOMAIN}`) every 15 minutes for DMARC aggregate reports, parses them, and exposes Prometheus metrics on port 9797. The mailbox is served by the `mailu-front` service in the same namespace. Reports are moved to `Archive` after successful parsing or `Invalid` if malformed. Deduplication state (report IDs seen in the last 7 days) is persisted to a 1Gi NFS-backed PVC to prevent double-counting reports delivered multiple times.

## Architecture at a glance
- **Depends on:** Mailu front service (IMAPS on port 993), ExternalSecret → 1Password item `mailu`, NFS storage class `zfs-nfs`
- **Depended on by:** Prometheus (scrapes metrics every 5 minutes via ServiceMonitor)

The Kustomization deliberately does **not** depend on the `mailu` Kustomization (`kubernetes/apps/mail/dmarc-exporter/ks.yaml` line 13 comment): losing DMARC visibility exactly when the mail stack is unhealthy would defeat the purpose of monitoring.

## Secrets
| ExternalSecret | 1Password item | Field | Consumer |
| --- | --- | --- | --- |
| `dmarc-exporter-config` | `mailu` | `DMARC_MAILBOX_PASSWORD` | Templated into `dmarc-metrics-exporter.json` as `imap.password` field, mounted at `/config` in the `exporter` container |

The entire exporter configuration file is generated by the ExternalSecret's template engine (`kubernetes/apps/mail/dmarc-exporter/app/externalsecret.yaml` lines 25–48) because the upstream exporter reads credentials from the JSON config file inline and has no environment-variable injection mechanism.

## Routing & access
- **No public exposure.** Metrics endpoint is internal-only.
- **Prometheus scrape:** ServiceMonitor (`kubernetes/apps/mail/dmarc-exporter/app/deployment.yaml` lines 105–116) configures a 5-minute scrape interval (longer than the default 1m because the exporter only polls IMAP every 15 minutes).
- **Network policy:** CiliumNetworkPolicy allows:
  - Ingress from `monitoring/prometheus` and kubelet (host entity) to port 9797
  - Egress to `kube-system/kube-dns` (UDP/TCP 53) and `mail/mailu-front` (TCP 993)

The exporter connects to Mailu via **IMAPS on port 993** using the public hostname `mail.${SECRET_DOMAIN}` rather than the Service ClusterIP (`kubernetes/apps/mail/dmarc-exporter/app/ciliumnetworkpolicy.yaml` lines 32–37 comment). This is intentional: CoreDNS's hosts plugin resolves that hostname to `mailu-front`'s ClusterIP, and the TLS certificate names it, so the connection is both encrypted and certificate-verified. Cilium does not encrypt pod-to-pod traffic in this cluster (no WireGuard or IPsec), so plain IMAP on port 143 would expose the mailbox password in cleartext on the pod network.

## Storage
- **PVC:** `dmarc-exporter`, 1Gi, `ReadWriteOnce`, StorageClass `zfs-nfs` (`kubernetes/apps/mail/dmarc-exporter/app/deployment.yaml` lines 78–86)
- **Purpose:** Deduplication state only (report IDs seen in the last 7 days, per `deduplication_max_seconds: 604800` in the config template)
- **Backup coverage:** TODO — verify whether this PVC is included in any Velero/Kopia schedule under `kubernetes/apps/velero/`

The Deployment uses `strategy.type: Recreate` (`kubernetes/apps/mail/dmarc-exporter/app/deployment.yaml` lines 10–12) because the PVC is RWO and two pods would double-count reports.

## Known quirks
- **Mailbox created 2026-09-20:** The `dmarc@${SECRET_DOMAIN}` mailbox was created in Mailu on this date (`kubernetes/apps/mail/dmarc-exporter/app/externalsecret.yaml` line 8 comment). The mailbox is receive-only; nothing sends from it.
- **Scrape interval mismatch is intentional:** Prometheus scrapes every 5 minutes, but the exporter polls IMAP every 15 minutes (`kubernetes/apps/mail/dmarc-exporter/app/deployment.yaml` line 115 comment). Scraping more frequently would only re-read the same counters.
- **Decoupled from Mailu health:** The Kustomization does not depend on `mailu` to avoid losing DMARC visibility when the mail stack is down (`kubernetes/apps/mail/dmarc-exporter/ks.yaml` lines 13–15).

## Common operations
- **Check metrics:** `kubectl port-forward -n mail svc/dmarc-exporter 9797:9797`, then `curl http://localhost:9797/metrics`
- **Force IMAP poll:** Restart the pod: `kubectl rollout restart -n mail deployment/dmarc-exporter` (the exporter has no signal-based trigger; it polls on a fixed 15-minute interval)
- **Rotate IMAP password:** Update the `DMARC_MAILBOX_PASSWORD` field in the 1Password `mailu` item, then force ExternalSecret refresh: `kubectl annotate externalsecret dmarc-exporter-config -n mail force-sync=$(date +%s)`. The pod will pick up the new config on its next restart (Reloader watches the `dmarc-exporter-config` secret and will restart the Deployment automatically, per the annotation on line 23 of `kubernetes/apps/mail/dmarc-exporter/app/deployment.yaml`).
- **Inspect deduplication state:** `kubectl exec -n mail deployment/dmarc-exporter -- ls -lh /var/lib/dmarc-metrics-exporter`
- **Pause reconciliation:** `flux suspend kustomization dmarc-exporter -n mail`
