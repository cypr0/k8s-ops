# Calendar Public

> **Namespace**  `mail`
> **Source**     plain manifests (`kubernetes/apps/mail/calendar-public/`), image `nginxinc/nginx-unprivileged`
> **Hostname**   `cal.${SECRET_DOMAIN}` — public, via `envoy-external` Gateway

## What it does here
Publishes selected private Radicale calendars (Mailu's `webdav`) as read-only `.ics` feeds that need no login, so clients that can only subscribe to a plain URL (Google Calendar, many web tools) can use them. Each feed lives at an unguessable path `https://cal.${SECRET_DOMAIN}/<token>.ics`; anyone holding the link sees the full calendar, including event details.

## Architecture at a glance
- **Depends on:** Mailu `webdav`/Radicale (`mailu-webdav.mail.svc.cluster.local:5232`), ExternalSecret → 1Password item `calendar-public`, ESO `Password` generator.
- **Depended on by:** nothing in-cluster; external calendar subscribers.
- The nginx proxy sets `X-Remote-User` itself and fetches `GET /<mailbox>/<collection-id>/` from Radicale, which trusts that header (`auth.type = http_x_remote_user`, `rights = owner_only`). Radicale returns the whole collection as `text/calendar`. Client-supplied `Authorization`, `Cookie` and `X-Forwarded-For` are dropped.

## Secrets
| ExternalSecret | Source | Consumer |
| --- | --- | --- |
| `calendar-public` → Secret `calendar-public-nginx` | 1Password item `calendar-public`: `FEED_1_USERNAME`, `FEED_1_COLLECTION`, `FEED_2_USERNAME`, `FEED_2_COLLECTION` (mailbox address and Radicale collection id per feed); plus two tokens generated by the `calendar-public-token` Password generator | Mounted as `/etc/nginx/conf.d/default.conf` |

Collection ids: `kubectl -n mail exec deploy/mailu-webdav -- sh -c 'grep -l VCALENDAR /data/collection-root/*/*/.Radicale.props'` lists the calendar directories (the directory name is the id, its parent the mailbox).

## Routing & access
- `envoy-external` → Service `calendar-public:8080`; DNS is created automatically from the HTTPRoute.
- Only `GET`/`HEAD` (and CORS `OPTIONS`) on the exact token paths are proxied; everything else returns 404.
- nginx's access log omits the request URI because it contains the token. Envoy's access log still contains it.

## Known quirks
- **Feed normalization (`feed.js`, njs body filter):** Radicale's export is rewritten on the fly because Daely's parser (Dart `icalendar_parser`) rejects the *entire* feed on one bad line. It fixes `GEO` values with an escaped separator (`lat\;lon` → `lat;lon`), drops a `TZID` property inside a `VEVENT`, and strips `;VALUE=TEXT` from `X-WR-CALNAME`/`X-WR-CALDESC`. `Content-Disposition` is dropped too, and CORS is open (`*`) for browser clients. The stock `nginx.conf` is replaced via `subPath` only to `load_module` njs, so re-check it when the image tag changes. Memory: the filter buffers the whole feed (~1 MB hex) per request, so keep the 64Mi limit in mind before adding more feeds or very large calendars.
- Tested with `icalendar_parser` 2.1.0 (`dart run` with `ICalendar.fromString` on the downloaded feed).
- Tokens are generated with `refreshPolicy: CreatedOnce`, so they stay stable. Rotate a token by deleting Secret `calendar-public-nginx` (all feed URLs change). The mailbox/collection fields are only read at that time too; after changing them in 1Password, delete the Secret as well.
- Radicale, not nginx, enforces what is readable: the proxy only ever requests the configured collection.

## Common operations
- Read the feed URLs: `kubectl -n mail get secret calendar-public-nginx -o jsonpath='{.data.default\.conf}' | base64 -d | grep 'location = /[A-Za-z0-9]'`
- Test: `curl -s https://cal.<domain>/<token>.ics | head`
